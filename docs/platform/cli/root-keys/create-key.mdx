Create a root key for the authenticated workspace.
Requires `unkey:v1:<workspace_id>:rootKeys/*#write`.
The created root key cannot have more permissions than the caller.

Save the returned secret securely. You can't retrieve it later. The permission array may be empty, but an empty set grants no access. Use `--body` to send an empty array.

## Usage

```bash
unkey root-keys create --permissions=<permissions> [flags]
```

## Flags

<ParamField body="--expires" type="integer">
  Expiration as Unix milliseconds, strictly in the future. Expiring root-key callers must provide a child expiry no later than their own. JWT admins and nonexpiring root-key callers may omit it or set null for no expiration. The flag accepts an integer. Use `--body` to send `expires: null`.
</ParamField>

<ParamField body="--name" type="string">
  Optional name for the root key.
</ParamField>

<ParamField body="--permissions" type="string[]" required>
  Permissions to grant to the root key. Each permission must be within the caller's existing permissions. Pass comma-separated permission URNs. To create a key with no permissions, use `--body` with `permissions: []`.
</ParamField>

</ParamField>

</ParamField>

## Examples

```bash
unkey root-keys create --name=automation --permissions='unkey:v1:ws_example:rootKeys/*#read'
```

Send the request body as JSON:

```bash
unkey root-keys create --body='{"name":"automation","permissions":[]}'
```

## API endpoint

The command calls `POST /v2/rootKeys.createKey` and prints its response. See the <a href="https://github.com/unkeyed/unkey/blob/main/svc/api/openapi/spec/paths/v2/rootKeys/createKey/index.yaml" target="_blank">endpoint definition</a> for the HTTP contract. Request fields use camelCase in `--body`.
