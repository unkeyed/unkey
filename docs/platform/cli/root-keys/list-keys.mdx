List readable root keys in the authenticated workspace, ordered by key ID.
Requires `unkey:v1:<workspace_id>:rootKeys/<key_id>#read` for each returned key.
Use `rootKeys/*#read` to read all root keys. Write permission does not imply read.
A caller with no readable keys receives an empty page.

Includes disabled and expired keys from the root-key store.
Deleted keys are excluded. Secrets and hashes are never returned.
Pass the returned cursor when hasMore is true to retrieve the next page.

## Usage

```bash
unkey root-keys list [flags]
```

## Flags

<ParamField body="--cursor" type="string">
  Opaque cursor from a previous response. Omit for the first page.
</ParamField>

<ParamField body="--limit" type="integer" default="100">
  Maximum number of readable root keys per page. Range: 1 to 100.
</ParamField>

## Examples

```bash
unkey root-keys list --limit=20
```

Send the request body as JSON:

```bash
unkey root-keys list --body='{"limit":20}'
```

## API endpoint

The command calls `POST /v2/rootKeys.listKeys` and prints its response. See the <a href="https://github.com/unkeyed/unkey/blob/main/svc/api/openapi/spec/paths/v2/rootKeys/listKeys/index.yaml" target="_blank">endpoint definition</a> for the HTTP contract. Request fields use camelCase in `--body`.
