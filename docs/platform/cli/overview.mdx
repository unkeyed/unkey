The `unkey` CLI manages Unkey resources from your terminal. Use a resource followed by an action, such as `unkey projects list`, `unkey keys create`, or `unkey deployments get`. Nearly every bearer-authenticated API endpoint has a matching command. Customer portal end-user endpoints use a portal session and aren't exposed by the CLI.

Sign in once, then run a resource command:

```bash
unkey login
unkey projects list
```

The default output is for reading in a terminal. Use `--json` for scripts and pipes. See [Output formats](/platform/cli/output-and-flags#output-formats).

Delete and remove commands also require confirmation. Review the target in the terminal prompt, or pass `--yes` explicitly in scripts. See [Confirm destructive commands](/platform/cli/output-and-flags#confirm-destructive-commands).

<Warning>
  The CLI is early and best effort. Commands, flags, and output can change without notice. The HTTP API is versioned and stable, so use the API for scripts that must not break.
</Warning>

## Command shape

Commands look like `unkey <resource> <action> [flags]`. Subresources add a level, such as `unkey environments variables list` or `unkey keys permissions add`. `unkey --help`, `unkey projects list --help`, and `unkey help projects list` print usage. `unkey version` and `unkey --version` print the installed CLI version.

Resource commands share authentication, output, debugging, and raw-body flags. See [CLI output and shared flags](/platform/cli/output-and-flags) for their behavior and syntax.

The legacy `unkey api <group> <command>` paths remain available for compatibility. These pages teach the resource paths without changing their existing documentation URLs.

## Command groups

Each resource command has its own page in the CLI section of its product.

### Compute

<Tooltip tip="A Compute app: a deployable service inside a project. Not 'your application' in general.">Apps</Tooltip>, deployments, domains, <Tooltip tip="A production or preview environment of a Compute app, not the dashboard label on a key.">environments</Tooltip>, gateway policies, and the GitHub App installation are Compute resources.

| Group | What it manages |
| --- | --- |
| [`unkey projects`](/compute/cli/projects/create-project) | Create, read, update, and delete workspace <Tooltip tip="Groups of apps, usually one per codebase or product.">projects</Tooltip> |
| [`unkey apps`](/compute/cli/apps/create-app) | Create, read, update, and delete apps within projects |
| [`unkey environments`](/compute/cli/environments/list-environments) | Environments, variables, and settings |
| [`unkey deployments`](/compute/cli/deployments/create-deployment) | Create and control deployments |
| [`unkey domains`](/compute/cli/domains/create-domain) | Create, read, <Tooltip tip="Here: proving DNS ownership of a custom domain. Not key verification.">verify</Tooltip>, and delete custom domains |
| [`unkey gateway policies`](/compute/cli/gateway/list-policies) | List, replace, and update gateway policies |
| [`unkey github`](/compute/cli/github/install-app) | GitHub App installations |
| `unkey analytics` | [`analytics gateway-requests`](/compute/cli/analytics/get-gateway-requests) and [`analytics runtime-logs`](/compute/cli/analytics/get-runtime-logs) query gateway and runtime data |

### API Management

Keyspaces, keys, identities, permissions and roles, <Tooltip tip="Here: the standalone rate limiting API and its overrides. Not key rate limits or gateway policies.">rate limiting</Tooltip>, and the customer portal are API Management resources.

| Group | What it manages |
| --- | --- |
| [`unkey apis`](/api-management/cli/apis/create-api) | Keyspaces (the API namespaces keys belong to) |
| [`unkey keys`](/api-management/cli/keys/create-key) | Create, list, <Tooltip tip="Here: checking an API key on a request. Not domain verification.">verify</Tooltip>, update, and delete keys and their permissions and roles |
| [`unkey identities`](/api-management/cli/identities/create-identity) | Identities that group keys |
| [`unkey permissions`](/api-management/cli/permissions/create-permission) | Permissions |
| [`unkey roles`](/api-management/cli/permissions/create-role) | Roles and their permissions |
| [`unkey ratelimit`](/api-management/cli/ratelimit/limit) | Rate limit checks and overrides |
| [`unkey portals`](/api-management/cli/portal/create-session) | Customer portals and their sessions |
| `unkey analytics` | [`analytics verifications`](/api-management/cli/analytics/get-verifications) and [`analytics ratelimits`](/api-management/cli/analytics/get-ratelimits) query key and rate limit data |

`analytics` appears in both tables because two of its commands read Compute data and two read API Management data.

## Top-level commands

Authentication, deployment, health checks, and the CLI version have their own command forms.

| Command | Product | What it does |
| --- | --- | --- |
| `unkey deploy <image>` | Compute | Deploys a prebuilt container image to a project and waits until the deployment is active. Needs `--project` (or `UNKEY_PROJECT`). Uses `--root-key`, then `UNKEY_ROOT_KEY`, then `unkey login`. Reference: [unkey deploy](/compute/cli/deploy). |
| `unkey login` | Platform | Signs you in with a device code and stores a CLI session. `--root-key=-` stores an existing root key instead. Reference: [unkey login](/platform/cli/login). |
| `unkey logout` | Platform | Revokes the active CLI session. |
| `unkey workspace switch` | Platform | Changes the active signed-in workspace. |
| `unkey auth login` | Platform | Same command and flags as [unkey login](/platform/cli/login). |
| `unkey healthcheck <url>` | Compute | Sends one HTTP GET and exits 0 on a 200 response, or 1 otherwise. Useful in CI and monitoring scripts. Reference: [unkey healthcheck](/compute/cli/healthcheck). |
| `unkey version` | Platform | Prints the installed CLI version to stdout, the same as `unkey --version`. |

`unkey version` does not manage deployments. To inspect, list, or roll back deployments, use [deployments get](/compute/cli/deployments/get-deployment), [deployments list](/compute/cli/deployments/list-deployments), or [deployments rollback](/compute/cli/deployments/rollback-deployment).
