Unkey is a platform for running and protecting APIs. It has two products. Use either one on its own, or both together.

<Columns cols={2}>
  <Card title="Compute" icon="server" href="/compute">
    Deploy an app from a GitHub repository or a container image. Unkey builds and runs it in production and preview environments, with automatic domains and a gateway in front of every deployment.
  </Card>
  <Card title="API Management" icon="key" href="/api-management">
    Issue API keys for your public API and verify them on every request, with rate limits, permissions, and usage credits in the same check. Your app runs wherever it runs today.
  </Card>
</Columns>

With both, the Compute gateway can check API keys from your keyspaces and rate limit callers before a request reaches your app, so your code doesn't need to call `keys.verifyKey`. See [API key authentication](/compute/gateway/api-key-auth).

Both products live in a [workspace](/platform/workspace/overview), the top-level container for everything you create. The workspace holds your team and their roles, and one billing account where each product has its own plan. You work with it through the dashboard at `app.unkey.com`, the HTTP API at `api.unkey.com`, the SDKs, and the `unkey` CLI. Root keys authenticate the API and SDKs, and the CLI accepts a root key or a session from `unkey login`. This section covers those shared pieces in detail.

## Self-hosting

These docs cover hosted Unkey: the dashboard at `app.unkey.com` and the API at `api.unkey.com`. The [source](https://github.com/unkeyed/unkey) is public, and most of it is licensed under FSL-1.1-ALv2 (see [`LICENSE`](https://github.com/unkeyed/unkey/blob/main/LICENSE) for the exceptions), so you can fork and run it under those terms. There's no self-hosting guide. Security fixes land on `main` and the latest release but they aren't backported, so you will want to run one of those for the most up-to-date security features.
