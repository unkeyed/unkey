Connect a GitHub repository to an <Tooltip tip="A Compute app: a deployable service inside a project. Not 'your application' in general.">app</Tooltip> and Unkey builds and deploys it on every push. By the end of this guide you have a <Tooltip tip="A group of apps, usually one per codebase or product.">project</Tooltip>, an app connected to the repository, and a production <Tooltip tip="One built and running version of an app in one environment.">deployment</Tooltip> live on a `unkey.app` domain.

To deploy an image you built yourself instead, see [Deploy a container image](/compute/get-started/deploy-an-image).

<Note>
    You need a Compute plan before you can deploy. If you don't have one yet, the dashboard asks you to pick one the first time you try (the dialog is titled **Choose a Compute plan**). Only a workspace admin can do that. See [Compute plans](/compute/get-started/plans) for what each plan includes.
</Note>

<Steps titleSize="h3">
  <Step title="Create a project">
    Open **Projects** in the dashboard and choose **Create project**. Enter a **Project Name**. The **Slug** is generated from it and is what you pass to the API and the CLI. You can edit it, but it must be unique in your workspace, and `default` is reserved.

    <Frame>
      <img src="/images/dashboard/compute--get-started-deploy-from-github--create-project.png" alt="Create New Project dialog with a project name and the slug generated from it" />
    </Frame>

    The dashboard then opens the new-app flow. To add an app to a project later, open the project and choose **Create app**.
  </Step>
  <Step title="Pick the repository">
    On **Deploy a new app**, pick **GitHub repository**.

    <Frame>
      <img src="/images/dashboard/compute--get-started-deploy-from-github--source.png" alt="Deploy a new app card offering GitHub repository or Container image, next to the steps Select a source, Choose your app, and Configure and deploy" />
    </Frame>

    If GitHub isn't connected to your workspace yet, choose **Connect GitHub** instead. It sends you to GitHub to install the Unkey GitHub App on an account or organization and choose repositories, then brings you back. The installation belongs to the workspace, so you only do this once.

    Click a repository to create the app, named after the repository (with `-2`, `-3`, and so on if the project already has an app by that name). The account menu above the list switches between GitHub accounts and organizations, and **Add GitHub account** at the bottom adds another. If a repository is missing from a listed account, choose **Can't find it? Add repositories on GitHub**.

    <Frame>
      <img src="/images/dashboard/compute--get-started-deploy-from-github--select-repository.png" alt="Import a GitHub repository card with an account filter, a search field, and a list of repositories" />
    </Frame>
  </Step>
  <Step title="Check app configuration">
    The default configuration is enough to build and run most repositories without changes:

    - **Branch**: the repository's default branch.
    - **Build**: with no Dockerfile set, Unkey detects your language and toolchain and builds the image. See [Build settings](/compute/configure/build-settings).
    - **Scaling**: 0.25 vCPU, 256 MiB of memory, and one instance in `us-east-1`. See [Runtime settings](/compute/configure/runtime-settings).
    - **Environment variables**: mark secrets as sensitive to make them write-only. See [Environment variables](/compute/configure/environment-variables).

    Build and scaling settings you save here apply to both the production and preview <Tooltip tip="A production or preview environment of a Compute app, not the dashboard label on a key.">environments</Tooltip>, and auto deploy is enabled for both by default. Your container must listen on the port in the `PORT` environment variable, which is 8080 by default. The port can be changed for each environment individually later by navigating to **App settings** > **Environments**, selecting the environment, and clicking **Configure** on the **Runtime** card.

    If you go back and pick a different repository, Unkey connects it to the same app. Leaving before you deploy asks you to discard the app.
  </Step>
  <Step title="Deploy">
    Choose **Deploy**. The dashboard deploys the head of the branch to production and opens the deployment page, where the build log streams. The deployment moves through `pending`, `starting`, `building`, `deploying`, `network` (shown as **Assigning Domains**), and `finalizing` to `ready`. If another deployment in the workspace is running, it waits its turn.

    <Frame>
      <img src="/images/dashboard/compute--get-started-deploy-from-github--deployment.png" alt="Deployment page for a ready production deployment showing its commit, resources, instances, domains, and network" />
    </Frame>

    At `ready` the app is live. For project `payments`, app `api`, and workspace `acme`, production answers on `payments-api-acme-a1b2c3.unkey.app` (or `payments-acme-a1b2c3.unkey.app` if the app slug is `default`), where `a1b2c3` is the app code. The deployment page also lists domains for the environment, the branch, and the exact commit.

    If the deployment ends `failed`, the page shows the failed step and an error code. [Deployments](/compute/concepts/deployments) lists the codes and how to fix them.
  </Step>
  <Step title="Push again">
    From now on GitHub tells Unkey about every push.

    - A push to the default branch creates a production deployment. When it reaches `ready`, it becomes the live deployment and the production domains move to it.
    - A push to any other branch creates a preview deployment with its own branch domain, so every branch has a URL you can share.
    - A pull request from a fork waits in `awaiting_approval` until a project member approves it, because it runs code from outside your repository.

    Your auto deploy settings and watch paths determine which pushes get built, and a push that isn't built is recorded as `skipped` with the reason.
  </Step>
</Steps>

<Visibility for="agents">
  The same flow through the API, with a root key in `Authorization: Bearer`. Each call is an HTTP `POST` to `https://api.unkey.com/v2/...` with a JSON body. Required permissions: `project.*.create_project`, `workspace.*.install_github`, `project.*.create_app`, `app.*.connect_repository` (only when `createApp` carries a `git.repository`), `environment.*.create_deployment`, and `unkey:v1:<workspace_id>:projects/*/apps/*/environments/*/deployments/*#read`.

  <CodeGroup>
    ```bash Create the project
    curl -X POST https://api.unkey.com/v2/projects.createProject \
      -H "Authorization: Bearer $UNKEY_ROOT_KEY" \
      -H "Content-Type: application/json" \
      -d '{"name":"Payments","slug":"payments"}'
    ```
    ```bash Install the GitHub App
    # Returns a GitHub URL to open in a browser; installation is workspace wide.
    curl -X POST https://api.unkey.com/v2/github.installApp \
      -H "Authorization: Bearer $UNKEY_ROOT_KEY" \
      -H "Content-Type: application/json" \
      -d '{}'
    ```
    ```bash Create the app with its repository
    curl -X POST https://api.unkey.com/v2/apps.createApp \
      -H "Authorization: Bearer $UNKEY_ROOT_KEY" \
      -H "Content-Type: application/json" \
      -d '{"project":"payments","name":"Payments API","slug":"api","git":{"repository":"acme/payments"}}'
    ```
    ```bash Deploy the default branch to production
    curl -X POST https://api.unkey.com/v2/deployments.createDeployment \
      -H "Authorization: Bearer $UNKEY_ROOT_KEY" \
      -H "Content-Type: application/json" \
      -d '{"project":"payments","app":"api","environment":"production","git":{}}'
    ```
    ```bash Poll until ready
    curl -X POST https://api.unkey.com/v2/deployments.getDeployment \
      -H "Authorization: Bearer $UNKEY_ROOT_KEY" \
      -H "Content-Type: application/json" \
      -d '{"deploymentId":"d_..."}'
    ```
  </CodeGroup>

  `getDeployment` returns `status`, `domains`, `availableActions`, and, when the status is `failed`, an `error` with a `code`. Poll until the status is one of `ready`, `failed`, `skipped`, `superseded`, `stopped`, or `cancelled`.
</Visibility>
