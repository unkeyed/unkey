You can deploy an app straight from a GitHub repository, and Unkey deploys on every push. Connect the repository and Unkey tracks its default branch on GitHub. A push to that branch creates a production <Tooltip tip="One built and running version of an app in one environment.">deployment</Tooltip>. A push to any other branch creates a preview deployment. Open the deployment in the dashboard and wait for its status to be `ready`. Then it's live on a `unkey.app` domain.

That's the default, with auto deploy on and no watch paths. If you turn auto deploy off or set watch paths, a push can be recorded as `skipped` instead of built. A pull request from a fork waits in `awaiting_approval` until a project member approves it.

An <Tooltip tip="A Compute app: a deployable service inside a project. Not 'your application' in general.">app</Tooltip> deploys and serves traffic. By the end of this guide you have a project, an app connected to the repository, and a production deployment.

If you'd rather bring an image you built yourself, see [Deploy a container image](/compute/get-started/deploy-an-image).

<Note>
    You need a Compute plan before you can deploy. If you don't have one yet, the dashboard asks you to pick one the first time you try (the dialog is titled **Choose a Compute plan**). Only a workspace admin can do that. See [Compute plans](/compute/get-started/plans) for what each plan includes.
</Note>

<Steps titleSize="h3">
 
  <Step title="Create a project">
    Open **Projects** in the dashboard and choose **Create project**. The dialog asks for a **Project Name** and a **Slug**. The slug is generated from the name, and you can edit it. The slug is the identifier you'll pass to the API and the CLI, it must be unique in your workspace, and `default` is reserved.

    <Frame>
      <img src="/images/dashboard/compute--get-started-deploy-from-github--create-project.png" alt="Create New Project dialog with a project name and the slug generated from it" />
    </Frame>

    The dashboard then opens the new-app flow.
  </Step>
  <Step title="Pick the repository">
    On **Deploy a new app**, pick **GitHub repository**. To add an app to a project later, open the project and choose **Create app**.

    <Frame>
      <img src="/images/dashboard/compute--get-started-deploy-from-github--source.png" alt="Deploy a new app card offering GitHub repository or Container image, next to the steps Select a source, Choose your app, and Configure and deploy" />
    </Frame>

    If the workspace hasn't installed the Unkey GitHub App, the row reads **Connect GitHub** instead. It sends you to GitHub to install the app on an organization or personal account and choose repositories, then brings you back to the repository list. The installation belongs to the workspace, so you do it once.

    Click a repository. If it's missing, choose **Can't find it? Add repositories on GitHub**.

    <Frame>
      <img src="/images/dashboard/compute--get-started-deploy-from-github--select-repository.png" alt="Import a GitHub repository card with an account filter, a search field, and a list of repositories" />
    </Frame>

    This creates the app, named after the repository. If the project already uses that name, Unkey adds `-2`, `-3`, and so on.
  </Step>
  <Step title="Check the settings">
    The branch starts as the repository's default branch. The defaults build and run most repositories without changes:

    - **Build**: with no Dockerfile set, Unkey detects your language and toolchain and builds the image. See [Build settings](/compute/configure/build-settings).
    - **Scaling**: each app starts with 0.25 vCPU, 256 MiB of memory, and one instance in each region available to the workspace. See [Runtime settings](/compute/configure/runtime-settings).
    - **Environment variables**: mark secrets as sensitive to make them write-only. See [Environment variables](/compute/configure/environment-variables).

    Build and scaling settings you save here apply to both <Tooltip tip="A production or preview environment of a Compute app, not the dashboard label on a key.">environments</Tooltip>. Auto deploy starts on for both. Your container must listen on the port in the `PORT` environment variable. The port is set per environment and is 8080 in each one. To change it for one environment, open **App settings** > **Environments**, select the environment, and click **Configure** on the **Runtime** card.

    Going back keeps your saved settings. Picking a different repository connects it to the same app.

    Leaving before you deploy asks you to discard the app. An app that was never deployed reopens this flow.
  </Step>
  <Step title="Deploy">
    Choose **Deploy**. The dashboard creates a deployment in the production environment from the head of the selected branch and opens the deployment page. The deployment moves through `pending`, `starting`, `building`, `deploying`, `network` (shown as **Assigning Domains**), and `finalizing` before it reaches `ready`. The build log streams while `building` runs. A first build waits its turn if another deployment in the workspace is running.

    When the status is `ready` the app is live on its automatic domains. With a project `payments`, an app `api`, and a workspace `acme`, the production deployment answers on `payments-api-acme.unkey.app`, with further domains for the environment, the branch, and the exact commit. If the app slug is `default` the domains omit it and start with `payments-`. The deployment detail page lists every domain.

    <Frame>
      <img src="/images/dashboard/compute--get-started-deploy-from-github--deployment.png" alt="Deployment page for a ready production deployment showing its commit, resources, instances, domains, and network" />
    </Frame>

    If the deployment ends `failed`, the detail page shows the step that failed and an error code. [Deployments](/compute/concepts/deployments) lists the codes and what to change.
  </Step>
  <Step title="Push again">
    From now on GitHub tells Unkey about every push. A push to the app's default branch creates a production deployment, and when it reaches `ready` it becomes the live deployment and the production domains move to it. A push to any other branch creates a preview deployment with its own branch domain, so every branch has a URL you can share. A pull request from a fork is held in `awaiting_approval` until a project member approves it, because it runs code from outside your repository.

    Auto deploy and watch paths decide whether a push builds at all. A push that isn't built is recorded as `skipped` with the reason.
  </Step>
</Steps>

<Visibility for="agents">
  The same flow through the API, with a root key in `Authorization: Bearer`. Each call is an HTTP `POST` to `https://api.unkey.com/v2/...` with a JSON body. Required permissions: `project.*.create_project`, `workspace.*.install_github`, `project.*.create_app`, `app.*.connect_repository` (only when `createApp` carries a `git.repository`), `environment.*.create_deployment`, and `unkey:v1:<workspace_id>:projects/*/apps/*/environments/*/deployments/*#read`.

  <CodeGroup>
    ```bash Create the project
    curl -X POST https://api.unkey.com/v2/projects.createProject \
      -H "Authorization: Bearer $UNKEY_ROOT_KEY" \
      -H "Content-Type: application/json" \
      -d '{"name":"Payments","slug":"payments"}'
    ```
    ```bash Install the GitHub App
    # Returns a GitHub URL to open in a browser; installation is workspace wide.
    curl -X POST https://api.unkey.com/v2/github.installApp \
      -H "Authorization: Bearer $UNKEY_ROOT_KEY" \
      -H "Content-Type: application/json" \
      -d '{}'
    ```
    ```bash Create the app with its repository
    curl -X POST https://api.unkey.com/v2/apps.createApp \
      -H "Authorization: Bearer $UNKEY_ROOT_KEY" \
      -H "Content-Type: application/json" \
      -d '{"project":"payments","name":"Payments API","slug":"api","git":{"repository":"acme/payments"}}'
    ```
    ```bash Deploy the default branch to production
    curl -X POST https://api.unkey.com/v2/deployments.createDeployment \
      -H "Authorization: Bearer $UNKEY_ROOT_KEY" \
      -H "Content-Type: application/json" \
      -d '{"project":"payments","app":"api","environment":"production","git":{}}'
    ```
    ```bash Poll until ready
    curl -X POST https://api.unkey.com/v2/deployments.getDeployment \
      -H "Authorization: Bearer $UNKEY_ROOT_KEY" \
      -H "Content-Type: application/json" \
      -d '{"deploymentId":"d_..."}'
    ```
  </CodeGroup>

  `getDeployment` returns `status`, `domains`, `availableActions`, and, when the status is `failed`, an `error` with a `code`. Poll until the status is one of `ready`, `failed`, `skipped`, `superseded`, `stopped`, or `cancelled`.
</Visibility>
