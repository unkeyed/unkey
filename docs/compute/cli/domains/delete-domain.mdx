Delete a custom domain from your workspace, addressed by ID or name. We stop serving the name, and requests to it fail with a certificate error. Your DNS records stay in place, so remove them yourself.

## Usage

```bash
unkey domains delete --domain=<domain id or name>
```

## Required permissions

Your root key needs one of:

- `environment.*.delete_domain` (any environment)
- `environment.<environment_id>.delete_domain` (a specific environment)

If the domain doesn't exist or your key doesn't have the permission, you get the same 404: `The requested domain does not exist.` If your key can read the domain, you get a 403 that names the missing permission instead. See [Root key permissions](/platform/root-keys/permissions) for the full catalog.

## Examples

Delete a domain:

```bash
unkey domains delete --domain=api.acme.com
```

Send the request body as JSON:

```bash
unkey domains delete --body='{"domain":"api.acme.com"}'
```

## API endpoint

The command calls [`POST /v2/domains.deleteDomain`](/compute/api-reference/domains/delete-domain) and prints its response. The request fields carry the same names as the flags in camelCase, which is the shape `--body` expects.
