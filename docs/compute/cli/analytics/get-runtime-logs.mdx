Run a SQL query against the logs your deployments wrote. Query the `runtime_logs_v1` table. CTEs, subqueries, `UNION`, and `EXCEPT` all work.

You only see data from the root key's workspace. To narrow it to one <Tooltip tip="A group of apps, usually one per codebase or product.">project</Tooltip>, <Tooltip tip="A Compute app: a deployable service inside a project. Not your application in general.">app</Tooltip>, <Tooltip tip="A production or preview environment of a Compute app, not the dashboard label on a key.">environment</Tooltip>, or deployment, filter on `project_id`, `app_id`, `environment_id`, or `deployment_id`. Your plan's log query range limits how far back a query can reach, and analytics query quotas apply. See [Limits](/platform/billing/limits).

## Usage

```bash
unkey analytics runtime-logs --query=<sql>
```

## Required permissions

Your root key needs `project.*.read_runtime_logs`. A grant for one project, such as `project.<project_id>.read_runtime_logs`, doesn't work here.

Without a matching permission the API answers 403 and the CLI prints `Permission denied:` followed by the detail. See [Root key permissions](/platform/root-keys/permissions) for the full catalog.

## Examples

Latest log lines of one deployment:

```bash
unkey analytics runtime-logs --query="SELECT time, message FROM runtime_logs_v1 WHERE deployment_id = 'd_1234abcd' ORDER BY time DESC LIMIT 100"
```

Count lines by severity:

```bash
unkey analytics runtime-logs --query="SELECT severity, COUNT(*) AS total FROM runtime_logs_v1 WHERE environment_id = 'env_1234abcd' GROUP BY severity"
```

Send the request body as JSON:

```bash
unkey analytics runtime-logs --body='{"query":"SELECT COUNT(*) AS total FROM runtime_logs_v1"}' --output=json
```

## API endpoint

The command calls [`POST /v2/analytics.getRuntimeLogs`](/compute/api-reference/analytics/query-runtime-log-data) and prints its response. The request fields carry the same names as the flags in camelCase, which is the shape `--body` expects.
