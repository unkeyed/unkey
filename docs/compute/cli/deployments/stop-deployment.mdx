Stop a running preview deployment and free its compute resources. It keeps its configuration, and you can bring it back with `unkey deployments start`. It must be `ready` and in a preview <Tooltip tip="A production or preview environment of a Compute app, not the dashboard label on a key.">environment</Tooltip>. Production deployments can't be stopped. Stopping a deployment that's still shutting down from an earlier stop returns a precondition error. The command returns before the instances are gone. Poll `unkey deployments get` until the status is `stopped`.

## Usage

```bash
unkey deployments stop --deployment-id=<deployment id>
```

## Required permissions

Your root key needs write on the deployment:

- `unkey:v1:<workspace_id>:projects/<project_id>/apps/<app_id>/environments/<environment_id>/deployments/<deployment_id>#write`

If the deployment doesn't exist or your key doesn't have the permission, you get the same 404: `The requested deployment does not exist.` If your key can read the deployment, you get a 403 that names the missing permission instead. See [Root key permissions](/platform/root-keys/permissions) for the full catalog.

## Examples

Stop a preview deployment:

```bash
unkey deployments stop --deployment-id=d_1234abcd
```

Send the request body as JSON:

```bash
unkey deployments stop --body='{"deploymentId":"d_1234abcd"}'
```

## API endpoint

The command calls [`POST /v2/deployments.stopDeployment`](/compute/api-reference/deployments/stop-deployment) and prints its response. The request fields carry the same names as the flags in camelCase, which is the shape `--body` expects.
