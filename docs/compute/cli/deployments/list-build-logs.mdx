Retrieve the build output of a deployment as a list of log entries, in the
order the build printed them. A log entry is one chunk of build output,
and can contain several lines or part of a line.

Poll this endpoint to follow a running build:

- Send the `pagination.cursor` of the last response as `cursor`. The
  response contains only the entries after it.
- When `hasMore` is true, request again now.
- When `hasMore` is false, you have all entries so far. Wait,
  then request again with the same cursor.
- The cursor is absent only when the request had no cursor and the build
  has no entries yet.
- A response can contain fewer than `limit` entries and still have
  `hasMore: true` when the entries are large.

New entries become visible up to a few seconds after the build prints
them. To know that a build is done, check the deployment status with
[deployments get](/compute/cli/deployments/get-deployment). After the status is no longer `building`, request until
you get an empty response at least 5 seconds later.

When a build attempt is retried, an entry from the earlier attempt can
arrive after the cursor has moved past it, and a poll does not return it.
A request without a cursor returns it. A deployment from a prebuilt image
has no build and returns no entries. Build logs are kept for 3 months.

## Usage

```bash
unkey deployments build-logs list --deployment-id=<deployment-id> [flags]
```

## Flags

<ParamField body="--cursor" type="string">
  Pagination cursor from a previous response to fetch the entries after it. Omit it to start at the first entry of the build.
</ParamField>

<ParamField body="--deployment-id" type="string" required>
  Identifies the deployment by its unique ID or slug. Accepts a prefixed deployment ID such as `d_1234abcd` or a slug.
</ParamField>

<ParamField body="--limit" type="integer">
  Maximum number of log entries to return. A response can contain fewer entries and still have `hasMore: true` when the entries are large. Range: 1 to 500. The API defaults to 100 when omitted.
</ParamField>

<ParamField body="--step-id" type="string">
  Return only the log entries of this build step. Use the `stepId` of an entry from a previous response. An unknown step returns no entries. Omit this field to return the entries of every step.
</ParamField>

## Required permissions

Your root key must have the following permission:

- `unkey:v1:<workspace_id>:projects/<project_id>/apps/<app_id>/environments/<environment_id>/deployments/<deployment_id>/buildLogs#read`

See [Root key permissions](/platform/root-keys/permissions).

## Examples

```bash
unkey deployments build-logs list --deployment-id=d_1234abcd
```

```bash
unkey deployments build-logs list --deployment-id=d_1234abcd --cursor=1704067201000001 --limit=50
```

Send the request body as JSON:

```bash
unkey deployments build-logs list --body='{"deploymentId":"d_1234abcd","limit":50}'
```

## API endpoint

The command calls `POST /v2/deployments.listBuildLogs` and prints its response. See the <a href="https://github.com/unkeyed/unkey/blob/main/svc/api/openapi/spec/paths/v2/deployments/listBuildLogs/index.yaml" target="_blank">endpoint definition</a> for the HTTP contract. Request fields use camelCase in `--body`.
