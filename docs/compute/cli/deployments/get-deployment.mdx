Retrieve one deployment by ID: its lifecycle status, build steps, error messages, and runtime configuration. Use it to check progress after `unkey deployments create`, `unkey deployments promote`, `unkey deployments rollback`, `unkey deployments start`, or `unkey deployments stop`, which all return before the work is done. The statuses are explained in [Deployments](/compute/concepts/deployments#statuses).

## Usage

```bash
unkey deployments get --deployment-id=<deployment id>
```

## Required permissions

Your root key needs `unkey:v1:<workspace_id>:projects/<project_id>/apps/<app_id>/environments/<environment_id>/deployments/<deployment_id>#read`. Use `*` for any level to cover more deployments.

If the deployment doesn't exist or your key doesn't have the permission, you get the same 404: `The requested deployment does not exist.` See [Root key permissions](/platform/root-keys/permissions) for the full catalog.

## Examples

Get a deployment:

```bash
unkey deployments get --deployment-id=d_1234abcd
```

Poll until it is ready:

```bash
until [ "$(unkey deployments get --deployment-id=d_1234abcd --output=json | jq -r '.data.status')" = ready ]; do sleep 5; done
```

## API endpoint

The command calls [`POST /v2/deployments.getDeployment`](/compute/api-reference/deployments/get-deployment) and prints its response. The request fields carry the same names as the flags in camelCase, which is the shape `--body` expects.
