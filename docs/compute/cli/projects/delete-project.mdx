Delete a <Tooltip tip="A group of apps, usually one per codebase or product.">project</Tooltip> and all of its <Tooltip tip="Compute apps: deployable services inside a project. Not your applications in general.">apps</Tooltip>, <Tooltip tip="Production or preview environments of a Compute app, not the dashboard label on a key.">environments</Tooltip>, deployments, and custom domains.

Deletion runs in the background: a successful response means it has started, not that every resource is gone yet. A project with delete protection enabled is refused until you disable it with `unkey projects update`.

## Usage

```bash
unkey projects delete --project=<project>
```

## Required permissions

Your root key needs one of:

- `project.*.delete_project` (any project)
- `project.<project_id>.delete_project` (a specific project)

Without a matching permission the API answers 403 and the CLI prints `Permission denied:` followed by the detail. See [Root key permissions](/platform/root-keys/permissions) for the full catalog.

## Examples

Delete a project:

```bash
unkey projects delete --project=proj_1234abcd
```

Send the request body as JSON:

```bash
unkey projects delete --body='{"project":"payments"}'
```

## API endpoint

The command calls [`POST /v2/projects.deleteProject`](/compute/api-reference/projects/delete-project) and prints its response. The request fields carry the same names as the flags in camelCase, which is the shape `--body` expects.
