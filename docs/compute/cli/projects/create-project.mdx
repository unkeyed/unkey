Create a <Tooltip tip="A group of apps, usually one per codebase or product.">project</Tooltip>, the top-level Compute container that groups <Tooltip tip="Compute apps: deployable services inside a project. Not your applications in general.">apps</Tooltip> and their deployments under a slug that is unique in your workspace.

The slug is what you pass to later `--project` flags. It must be unique in the workspace, or you get a 409 conflict. Projects are described in [Projects, apps, and environments](/compute/concepts/projects-apps-environments).

Creating a project needs an active Compute plan. Without one the API answers 412 with `The workspace has no active Compute plan.` See [Compute plans](/compute/get-started/plans).

## Usage

```bash
unkey projects create --name=<name> --slug=<slug>
```

## Flags

<ParamField body="--name" type="string" required>
  Human-readable name for the project, shown in the dashboard. 1 to 256 characters.
</ParamField>

<ParamField body="--slug" type="string" required>
  Stable project slug, unique within the workspace. 3 to 255 characters matching `^[a-zA-Z0-9_-]+$`. Used in `--project` flags and in generated deployment hostnames.
</ParamField>

## Required permissions

Your root key needs `project.*.create_project`.

Without a matching permission the API answers 403 and the CLI prints `Permission denied:` followed by the detail. See [Root key permissions](/platform/root-keys/permissions) for the full catalog.

## Examples

Create a project:

```bash
unkey projects create --name='Payments Service' --slug=payments-service
```

Send the request body as JSON:

```bash
unkey projects create --body='{"name":"Payments Service","slug":"payments-service"}' --output=json
```

## API endpoint

The command calls [`POST /v2/projects.createProject`](/compute/api-reference/projects/create-project) and prints its response. The request fields carry the same names as the flags in camelCase, which is the shape `--body` expects.
