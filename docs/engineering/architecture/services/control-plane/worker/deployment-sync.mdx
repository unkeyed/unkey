---
title: "Deployment sync"
description: "How the control plane streams state changes to krane agents"
---

The deployment sync POC uses Vitess VStream to deliver topology changes from
Ctrl to Krane. It replaces the `deployment_changes` outbox. Workers write only
desired state. No separate event service or message broker is required.

## Follow a change

Each Krane watch opens one VStream through Ctrl:

1. Krane opens `WatchDeploymentChanges` with its cluster key and resume token.
2. Ctrl authenticates the request and resolves the cluster's region ID.
3. Ctrl opens a primary-tablet VStream with this filter:

```sql
select deployment_id from deployment_topology where region_id = 'region_id'
```

4. For each changed ID, Ctrl reads the current desired state from the primary
   database and sends an apply or delete event.
5. At a transaction boundary, Ctrl sends a checkpoint-only event containing the
   full VGTID, including snapshot table positions.
6. Krane applies events sequentially. It saves the token in memory only after
   all preceding events have succeeded.

This delivers current desired state, not a historical record of every status
transition. Updates to columns outside the filter projection still produce
events. Changes to joined tables without a topology mutation rely on full sync.

## Replay and recover

An empty token starts a region-filtered snapshot followed by live changes.
`replay = true` ignores the supplied token and starts that snapshot again.
Replay means copying current state, not replaying the old outbox from its start.

After a disconnect, Krane reconnects with its last successful token. An apply
failure closes the stream without advancing the checkpoint. Events can repeat,
so deployment operations must remain idempotent. Tokens are not persisted across
Krane restarts. A restart starts a fresh snapshot.

If Vitess reports unavailable binlogs with MySQL error 1236 or 1789, Ctrl returns
`OutOfRange`. Krane clears the token and requests a fresh snapshot. Other stream
errors retry the same token.

Krane also calls `SyncDesiredState` on startup and every 10 minutes. This RPC
loads running deployments without depending on binlog retention. Its existing
per-ReplicaSet reconciliation checks desired state every minute and removes
resources whose topology no longer exists. A missing topology is skipped by
the incremental stream because its Kubernetes metadata is no longer available.

## Handle slow consumers

The POC has no application event queue. Synchronous delivery and transport flow
control slow the reader when Krane falls behind. Binlogs provide the replay
window, but they are not a permanent event archive.

The observed PlanetScale setting `binlog_expire_logs_seconds = 259200` represents
3 days. It is not a guaranteed replay window across failover or database resets.
If the token becomes unusable, Krane recovers current state through a snapshot
and reconciliation rather than recovering every historical event.

## Run locally

The local Tilt database uses Vitess 24.0.3 with one unsharded `unkey` keyspace.
Existing SQL clients use `mysql:3306`. Ctrl uses `mysql:33575` for VStream:

```toml
[vstream]
address = "mysql:33575"
keyspace = "unkey"
insecure = true
```

The database loads the schema and local seed on first startup. It uses the
`vitess-pvc` volume, with no migration or preservation of the old MySQL volume.
Persistent Vitess skips schema and seed loading on later starts, so
schema changes require an explicit migration or a fresh Vitess-only volume.
The local Vitess SQL and gRPC endpoints do not enforce authentication.

Run the targeted tests from the repository root:

```bash
mise exec -- rask ./svc/ctrl/internal/deploymentstream \
  ./svc/ctrl/services/cluster ./svc/krane/internal/watcher
```

The VStream integration test starts a separate disposable Vitess service with
the repository schema. Ordinary database tests continue to use MySQL.

## Configure PlanetScale

Use the database's supported VStream gRPC address and keyspace. Configure
`username` and `password` in Ctrl's `[vstream]` section through secret-backed
environment expansion. TLS is enabled by default. Do not set `insecure = true`
outside local development. Credentials are sent through Basic authentication
over TLS and remain in Ctrl, not Krane.

PlanetScale supports VStream, but the local tests do not verify access or
retention for a particular production database. Confirm those with PlanetScale
before rollout. Multi-shard resharding, failover, and sustained slow-consumer
load are outside the POC's verification.

Ctrl and Krane must be updated together. The protobuf replaces numeric versions
with resume tokens and has no compatibility path. Existing production outbox
tables are not dropped by this code change. Remove them separately after rollout.
