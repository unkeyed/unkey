---
title: "Backfill project ownership"
description: "Create default projects and backfill project ownership for existing resources"
---

The project ownership migration creates a protected `default` project for each
workspace that doesn't have one. It assigns that project to existing APIs,
keyspaces, identities, roles, permissions, and rate-limit namespaces that have
an empty `project_id`.

The migration is idempotent. You can rerun it after a failure because it reuses
existing default projects and updates only rows where `project_id = ''`.

## Prepare the database

Deploy the six `project_id` columns and their indexes before running the
migration. Confirm that the application version deployed during the migration
still supports the transitional empty project ID.

Check for project slugs that can conflict with the exact `default` slug:

```sql
SELECT id, workspace_id, slug
FROM projects
WHERE LOWER(slug) = 'default' AND BINARY slug != 'default';
```

Resolve every returned row before continuing.

## Run the migration

Set `DRIZZLE_DATABASE_URL` to the target MySQL database and run the migration
from the repository root:

```bash
DRIZZLE_DATABASE_URL='<mysql-url>' \
  mise exec -- pnpm --dir=web/tools/migrate project-ownership
```

The command processes workspaces sequentially. It logs each created project,
the affected row counts for each table, and any workspace failures. A failed
workspace makes the command exit with a non-zero status after the remaining
workspaces finish.

## Complete the writer rollout

After the first migration pass, deploy the application version that writes a
non-empty `project_id` when it creates owned resources. Wait until all instances
running the previous version have stopped.

Run the migration command again after the writer rollout. This second pass
backfills resources created by an old application instance between the first
migration pass and the completed rollout. Do not remove the migration command
until this pass and the ownership verification succeed.

## Verify ownership

Every count in this query must be zero:

```sql
SELECT 'apis' AS table_name, COUNT(*) AS empty_project_ids
FROM apis WHERE project_id = ''
UNION ALL
SELECT 'key_auth', COUNT(*) FROM key_auth WHERE project_id = ''
UNION ALL
SELECT 'identities', COUNT(*) FROM identities WHERE project_id = ''
UNION ALL
SELECT 'roles', COUNT(*) FROM roles WHERE project_id = ''
UNION ALL
SELECT 'permissions', COUNT(*) FROM permissions WHERE project_id = ''
UNION ALL
SELECT 'ratelimit_namespaces', COUNT(*)
FROM ratelimit_namespaces WHERE project_id = '';
```

The following queries must return no rows. They prove that every workspace has
an exact default project and every API has the same project owner as its
keyspace:

```sql
SELECT w.id AS workspace_id
FROM workspaces w
LEFT JOIN projects p
  ON p.workspace_id = w.id AND BINARY p.slug = 'default'
WHERE p.id IS NULL;

SELECT a.id AS api_id,
  a.project_id AS api_project_id,
  ka.project_id AS keyspace_project_id
FROM apis a
INNER JOIN key_auth ka ON ka.id = a.key_auth_id
WHERE a.project_id != ka.project_id;
```
