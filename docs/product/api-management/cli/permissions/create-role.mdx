Create a role. A role groups permissions so you can give a key many at once. Calls `POST /v2/permissions.createRole`. See [Roles and permissions](/api-management/authorization/roles-and-permissions).

## Usage

```bash
unkey api permissions create-role --name=<name> [flags]
```

## Flags

<ParamField body="--name" type="string" required>
  Role name, 1 to 128 characters. Unique per workspace. Reusing one returns 409 [`err:unkey:data:role_already_exists`](/errors/unkey/data/role_already_exists). Keys refer to roles by name.
</ParamField>

<ParamField body="--description" type="string">
  What the role is for.
</ParamField>

<ParamField body="--permissions" type="string[]">
  Comma-separated permission slugs to attach. Slugs that don't exist yet are created. Each slug is 1 to 128 characters matching `^[a-zA-Z0-9_:\-\.\*]+$`, the same as `create-permission`.
</ParamField>

### Shared flags

Every `unkey api` command takes these. See [CLI output and shared flags](/platform/cli/output-and-flags).

<ParamField body="--root-key" type="string">
  Root key used for the request. Falls back to `UNKEY_ROOT_KEY`, then to the key stored by `unkey auth login`.
</ParamField>

<ParamField body="--api-url" type="string" default="https://api.unkey.com">
  Base URL of the API. Falls back to `UNKEY_API_BASE_URL`. You don't normally need to set it.
</ParamField>

<ParamField body="--config" type="string" default="~/.unkey/config.toml">
  Path of the config file written by `unkey auth login`. Falls back to `UNKEY_CONFIG`.
</ParamField>

<ParamField body="--output" type="string">
  Output format. Falls back to `UNKEY_OUTPUT`. `json` prints the full response. Any other value prints the request ID and `data`.
</ParamField>

<ParamField body="--body" type="string">
  Send this JSON as the whole request body instead of using the command's flags. You can't combine it with them.
</ParamField>

## Required permissions

`rbac.*.create_role`, plus `rbac.*.add_permission_to_role` when `--permissions` is given. Creating new slugs also needs `rbac.*.create_permission`. See [Root key permissions](/platform/root-keys/permissions).

## Examples

```bash Create with permissions
unkey api permissions create-role --name=api_reader --permissions=documents.read,settings.view
```

Or send the whole request as JSON:

```bash Raw body
unkey api permissions create-role --body='{"name":"api_reader","description":"Read-only access","permissions":["documents.read"]}'
```
