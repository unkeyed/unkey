The gateway always records a basic log entry for each request. This entry powers the traffic and latency charts in the dashboard. You cannot turn it off.

The logging policy adds sensitive data to the log entries of matched requests: headers and bodies. This capture is opt-in. Each direction is a separate setting. Without an enabled logging policy, the gateway stores only the basic entries.

Add a logging policy with no match conditions to capture data for all traffic, or scope it with match conditions to capture data only for specific routes.

## Always logged

The gateway records this data for every request:

- HTTP method, host, and path
- Status code
- Request ID and timestamp
- Deployment and instance identifiers
- Region
- Latency breakdown

| Metric           | Description                                                |
| ---------------- | ---------------------------------------------------------- |
| Total latency    | End-to-end time from when the gateway received the request |
| Instance latency | Time your app spent processing the request                 |
| Gateway latency  | Overhead added by the gateway (policy evaluation, routing) |

## Opt-in capture

A logging policy has four independent settings. Each one adds data to the log entries of matched requests:

| Setting          | Captured data                                                                    |
| ---------------- | -------------------------------------------------------------------------------- |
| Request headers  | Request headers, query string, query parameters, user agent, and client IP       |
| Response headers | Response headers                                                                  |
| Request body     | Request body, up to the capture limit                                             |
| Response body    | Response body, up to the capture limit                                            |

Query data is grouped with request headers because URLs often carry secrets, for example `?api_key=...`. The user agent and client IP are grouped with request headers because they identify the client.

If more than one enabled logging policy matches a request, the gateway captures the union of their settings.

The gateway redacts sensitive values before it stores them. The `Authorization` header is always redacted. Headers and query parameters that carry API keys for the [API key policy](/platform/gateway/policies/api-key) are redacted too.

## View logs

Logs are available in the **Requests** tab of your project in the Unkey dashboard. You can filter by:

- Status code
- HTTP method
- Path
- Deployment
- Environment

The dashboard supports live streaming for real-time monitoring.

## Retention

Logs are retained for 30 days.
