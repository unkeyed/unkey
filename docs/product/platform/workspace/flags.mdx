A workspace flag configures an Unkey feature for everyone in your workspace.
Unkey defines each flag and its default value. Workspace admins can set an
override when Unkey enables self-service changes for that flag.

Flags belong to the workspace, not to an individual member, project, or
environment. Available flags appear under **Settings > Flags**.

## Understand flag values

Each flag has one type. The value must match that type.

| Type | Input | Example |
| --- | --- | --- |
| Boolean | **Enabled** checkbox | Checked or unchecked |
| String | **Workspace value** text field | `balanced` |
| Number | **Workspace value** number field | `500` |

The **Default** badge means the workspace inherits the flag's default value.
The **Override** badge means the workspace has its own value. An override can
equal the default. Unchecked booleans, zero, and empty strings are valid
overrides, not missing values.

## Set an override

You must be a workspace admin to change an override. Other members can view
flag values, but their controls are disabled.

1. Navigate to **Settings > Flags**.
2. Find the flag and read its description and default value.
3. Check or uncheck **Enabled**, or enter a **Workspace value**.
4. Click **Set override**. For an existing override, click **Save changes**.

If value changes are managed by Unkey, the input and save button are disabled.
Some flags permit an override but don't permit you to remove it. These flags
show a notice before you save.

## Restore the default

If removal is permitted, click **Use default** on a flag with an override.
This removes the workspace override and restores the flag's default value.
Later changes to that default also apply to your workspace.

<Note>
  **Use default** does not necessarily disable a feature. If a boolean flag's
  default is `true`, removing its override enables it.
</Note>

If the flag says only Unkey can remove its override, **Use default** stays
disabled even for workspace admins.

## Handle errors

If flags fail to load, click **Retry**. If a save fails, the page shows an error
beside that flag. A failed request does not display a success confirmation.
After reloading the page, a recent change can take time to appear while database
replicas catch up.

If the page shows **No flags available**, Unkey has not made any flags available
to display. You don't need to create a flag.
