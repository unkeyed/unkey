---
title: "login"
description: "Sign in to the Unkey CLI with WorkOS OAuth (device flow), or store a root key. Run this once to authenticate all CLI operations."
---

Authenticate the CLI. By default `unkey auth login` signs you in with WorkOS OAuth using the device authorization flow, so you act as yourself with your organization and permissions. You can still store a root key with `--root-key`.

## OAuth login (default)

```bash
unkey auth login
```

The CLI prints a code and a URL and opens your browser. Confirm the code, sign in, and select your organization if prompted:

```text
To sign in, visit:

  https://auth.workos.com/device?code=WDJB-MJHT

and confirm this code: WDJB-MJHT

Only continue if you started this login yourself; never enter a code someone sent you.

Waiting for confirmation...

Logged in as james@unkey.com (org: Unkey)
```

Your access and refresh tokens are stored in `~/.unkey/config.toml` with `0600` permissions. Subsequent commands use the access token automatically and refresh it when it expires:

```bash
unkey api keys create-key --api-id=api_1234abcd --name="My Key"
```

<Note>
The access token carries your organization and permissions. If your account has no active organization membership, login fails with guidance rather than storing an unusable token.
</Note>

### Configuring the WorkOS client

The CLI ships with its public WorkOS client ID. To point at a different WorkOS environment (for example, a self-hosted setup), use `--workos-client-id` or the `UNKEY_WORKOS_CLIENT_ID` environment variable.

## Root key login (legacy)

To store a root key instead of an OAuth session:

```bash
unkey auth login --root-key
```

The command prompts for your root key (input is hidden) and saves it to `~/.unkey/config.toml`. Create a root key from the [Unkey dashboard](/platform/root-keys/overview).

## Credential precedence

When a command authenticates, credentials are resolved in this order:

1. `--root-key` flag or `UNKEY_ROOT_KEY` environment variable
2. A valid stored OAuth access token (refreshed automatically when expired)
3. A stored root key

```bash
# Flag always wins, even when an OAuth session exists
unkey api apis get-api --api-id=api_1234abcd --root-key=unkey_xxx
```

## Related commands

- [`unkey auth whoami`](/cli/auth/whoami) shows who you are signed in as.
- [`unkey auth logout`](/cli/auth/logout) clears stored credentials.
