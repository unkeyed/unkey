Retrieve a custom domain by ID or name and its <Tooltip tip="Here: proving DNS ownership of a custom domain. Not key verification.">verification</Tooltip> status. Names are unique per workspace, so `api.acme.com` is enough. No project, <Tooltip tip="A Compute app: a deployable service inside a project. Not your application in general.">app</Tooltip>, or <Tooltip tip="A production or preview environment of a Compute app, not the dashboard label on a key.">environment</Tooltip> is needed.

Use it to check progress after `create-domain`. We check DNS about once a minute.

- `status: verified` means routing is set up and a certificate has been requested.
- Each entry in `dnsRecords` has a `verified` flag, so you can see which records are still missing. A routing record your provider proxies or flattens can stay `false` even while it serves traffic.
- `verificationError` explains the last failed check.
- Verification stops 24 hours after `createdAt`, and the status becomes `failed`.

## Usage

```bash
unkey api domains get-domain --domain=<domain id or name>
```

## Flags

<ParamField body="--domain" type="string" required>
  Domain ID or fully qualified name.
</ParamField>

### Shared flags

Every `unkey api` command accepts these; [CLI output and shared flags](/platform/cli/output-and-flags) describes them in full.

<ParamField body="--body" type="string">
  A JSON document sent as the request body instead of building it from the flags above. It is mutually exclusive with the request-building flags, and unknown fields are rejected locally. See [Send a raw body](/platform/cli/output-and-flags#send-a-raw-body).

<ParamField body="--root-key" type="string">

<ParamField body="--config" type="string" default="~/.unkey/config.toml">
  Path of the TOML file that `unkey auth login` writes. Falls back to `UNKEY_CONFIG`.

<ParamField body="--output" type="string">
  Output format. Falls back to `UNKEY_OUTPUT`. Set `json` to print the full response envelope (`meta` and `data`) for piping; any other value prints the request ID followed by `data`.
</ParamField>

## Required permissions

Your root key needs one of:

- `environment.*.read_domain` (any environment)
- `environment.<environment_id>.read_domain` (a specific environment)

If the domain doesn't exist or your key doesn't have the permission, you get the same 404: `The requested domain does not exist.` See [Root key permissions](/platform/root-keys/permissions) for the full catalog.

## Examples

Check a domain:

```bash
unkey api domains get-domain --domain=api.acme.com
```

Print only the status:

```bash
unkey api domains get-domain --domain=api.acme.com --output=json | jq -r '.data.status'
```

## API endpoint

The command calls [`POST /v2/domains.getDomain`](/compute/api-reference/domains/get-domain) and prints its response. The request fields carry the same names as the flags in camelCase, which is the shape `--body` expects.
