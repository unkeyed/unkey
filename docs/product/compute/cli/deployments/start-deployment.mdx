Start a preview deployment that was stopped with `stop-deployment`, so it serves traffic again. Nothing is rebuilt, and it keeps the configuration it had. It must be in a preview <Tooltip tip="A production or preview environment of a Compute app, not the dashboard label on a key.">environment</Tooltip>, because production deployments can't be stopped. You don't need to wait for `stopped`: a deployment that's still shutting down can be started right away. The command returns before the deployment is back. Poll `get-deployment` until the status is `ready`.

Starting a deployment needs an active Compute plan. Without one the API answers 412 with `The workspace has no active Compute plan.` A workspace over its Compute spend cap gets `The workspace is suspended by its Compute spend cap. Raise the spend limit to resume.` See [Compute plans](/compute/get-started/plans).

## Usage

```bash
unkey api deployments start-deployment --deployment-id=<deployment id>
```

## Flags

<ParamField body="--deployment-id" type="string" required>
  ID of the stopped deployment to start.
</ParamField>

### Shared flags

Every `unkey api` command accepts these; [CLI output and shared flags](/platform/cli/output-and-flags) describes them in full.

<ParamField body="--body" type="string">
  A JSON document sent as the request body instead of building it from the flags above. It is mutually exclusive with the request-building flags, and unknown fields are rejected locally. See [Send a raw body](/platform/cli/output-and-flags#send-a-raw-body).
</ParamField>

<ParamField body="--root-key" type="string">
  Root key for the request. Falls back to `UNKEY_ROOT_KEY`, then to the config file written by `unkey auth login`. See [CLI authentication](/platform/cli/authentication).
</ParamField>

<ParamField body="--api-url" type="string" default="https://api.unkey.com">
  Base URL of the API. Falls back to `UNKEY_API_BASE_URL`. You don't normally need to set it.
</ParamField>

<ParamField body="--config" type="string" default="~/.unkey/config.toml">
  Path of the TOML file that `unkey auth login` writes. Falls back to `UNKEY_CONFIG`.
</ParamField>

<ParamField body="--output" type="string">
  Output format. Falls back to `UNKEY_OUTPUT`. Set `json` to print the full response envelope (`meta` and `data`) for piping; any other value prints the request ID followed by `data`.
</ParamField>

## Required permissions

Your root key needs one of:

- `environment.*.start_deployment` (any environment)
- `environment.<environment_id>.start_deployment` (a specific environment)

If the deployment doesn't exist or your key doesn't have the permission, you get the same 404: `The requested deployment does not exist.` See [Root key permissions](/platform/root-keys/permissions) for the full catalog.

## Examples

Start a stopped deployment:

```bash
unkey api deployments start-deployment --deployment-id=d_1234abcd
```

Send the request body as JSON:

```bash
unkey api deployments start-deployment --body='{"deploymentId":"d_1234abcd"}'
```

## API endpoint

The command calls [`POST /v2/deployments.startDeployment`](/compute/api-reference/deployments/start-deployment) and prints its response. The request fields carry the same names as the flags in camelCase, which is the shape `--body` expects.
