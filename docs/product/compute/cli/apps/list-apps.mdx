List the <Tooltip tip="Compute apps: deployable services inside a project. Not your applications in general.">apps</Tooltip> in a project. Results are ordered by app ID. When `pagination.hasMore` is true, pass `pagination.cursor` back with `--cursor`.

## Usage

```bash
unkey api apps list-apps --project=<project> [--limit=<n>] [--cursor=<cursor>] [--search=<text>]
```

## Flags

<ParamField body="--cursor" type="string">
  Pagination cursor from a previous response.
</ParamField>

<ParamField body="--limit" type="integer" default="100">
  Maximum number of apps per page, between 1 and 100.
</ParamField>

<ParamField body="--project" type="string" required>
  Project ID or slug. Both forms resolve to the same project.
</ParamField>

<ParamField body="--search" type="string">
  Free-form text, at most 256 characters. Returns apps whose ID, name, or slug contains it, matched case-insensitively.
</ParamField>

## Required permissions

Your root key needs `app.*.read_app`.

If the project doesn't exist or your key doesn't have the permission, you get the same 404: `The requested project does not exist.` See [Root key permissions](/platform/root-keys/permissions) for the full catalog.

## Examples

List the apps in a project:

```bash
unkey api apps list-apps --project=payments
```

Filter and page:

```bash
unkey api apps list-apps --project=payments --limit=25 --search=checkout
```

## API endpoint

The command calls [`POST /v2/apps.listApps`](/compute/api-reference/apps/list-apps) and prints its response. The request fields carry the same names as the flags in camelCase, which is the shape `--body` expects.
