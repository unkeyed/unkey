## What Happened?

You called `stopDeployment` on a deployment in the `production` environment. Production deployments serve live traffic and are never stopped directly; doing so would take the app offline. To move production off a deployment, promote or roll back to another one instead.

`getDeployment` reports the deployment's `environmentId`, and `availableActions` omits `stop` for production deployments.

## How To Fix

1. Fetch the deployment with `getDeployment` and inspect `availableActions`; `stop` is not listed for production deployments.
2. To change what production serves, use `promoteDeployment` or `rollbackDeployment` to move the live pointer.
3. The `stop` action only applies to non-production deployments.

```bash
# Move production traffic instead of stopping the live deployment
curl -X POST https://api.unkey.com/v2/deployments.rollbackDeployment \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer unkey_YOUR_API_KEY" \
  -d '{ "deploymentId": "d_5678wxyz" }'
```

## Common Mistakes

- **Trying to take production offline**: Using `stop` on a production deployment instead of promoting or rolling back.
- **Wrong environment**: Passing a production deployment id when you meant a preview one.
