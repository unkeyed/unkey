---

<Danger>`err:unkey:application:deployment_already_live`</Danger>

```json Example
{
  "meta": {
    "requestId": "req_2c9a0jf23l4k567"
  },
  "error": {
    "detail": "The deployment is already live.",
    "status": 412,
    "title": "Precondition Failed",
    "type": "https://unkey.com/docs/errors/unkey/application/deployment_already_live"
  }
}
```

## What Happened?

You called `promoteDeployment` or `rollbackDeployment` targeting the deployment that is already serving production traffic. In the normal case this would not change anything, so it is rejected to surface a likely mistake in the request rather than silently doing nothing.

The one exception is on `promoteDeployment`: if the app is currently in a rolled-back state, promoting the live deployment is allowed, because it confirms moving forward off the rollback instead of being a no-op. `rollbackDeployment` always rejects the current live deployment, whether or not the app is rolled back.

`getDeployment` reports `isCurrent: true` for the currently live deployment.

## How To Fix

1. Fetch the target with `getDeployment` and check `isCurrent`.
2. If you intended to change what is live, target a different deployment.
3. If the deployment is already live and that is what you want, no action is needed.

```bash
# Check whether the deployment is already live
curl -X POST https://api.unkey.com/v2/deployments.getDeployment \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer unkey_YOUR_API_KEY" \
  -d '{ "deploymentId": "d_1234abcd" }'
```

## Common Mistakes

- **Re-promoting the live deployment**: Promoting the deployment that is already live.
- **Stale deployment id**: Acting on an id that has since become the live deployment.
