<Danger>`err:unkey:application:no_live_deployment`</Danger>

```json Example
{
  "meta": {
    "requestId": "req_2c9a0jf23l4k567"
  },
  "error": {
    "detail": "The app has no live deployment to promote over.",
    "status": 412,
    "title": "Precondition Failed",
    "type": "https://unkey.com/docs/errors/unkey/application/no_live_deployment"
  }
}
```

## What Happened?

You called `promoteDeployment` or `rollbackDeployment`, but the app has no current live deployment. Promotion swaps the live pointer over the existing live deployment, and rollback derives its source from it, so both require an app that has already gone live at least once. A brand-new app that has never had a successful production deployment has no live pointer set.

## How To Fix

1. Deploy to production and wait for the deployment to reach `ready`.
2. Once the app has a live deployment, promote or roll back as needed.
3. Confirm the live deployment with `getDeployment`: the live one reports `isCurrent: true`.

```bash
# Verify the app has a live deployment
curl -X POST https://api.unkey.com/v2/deployments.getDeployment \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer unkey_YOUR_API_KEY" \
  -d '{ "deploymentId": "d_1234abcd" }'
```

## Common Mistakes

- **Promoting on a fresh app**: Trying to promote or roll back before the app has ever gone live.
- **Assuming a failed deploy went live**: A deployment that never reached `ready` does not set the live pointer.
