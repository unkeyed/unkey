<Danger>`err:unkey:authorization:insufficient_permissions`</Danger>

Your root key is valid, but it doesn't have a permission this endpoint needs. You get HTTP 403. On most endpoints, `detail` shows the permission that was missing.

```json Example response
{
  "meta": {
    "requestId": "req_2c9a0jf23l4k567"
  },
  "error": {
    "detail": "Insufficient permissions to access this resource.",
    "status": 403,
    "title": "Insufficient Permissions",
    "type": "/errors/unkey/authorization/insufficient_permissions"
  }
}
```

## Likely causes

- The root key was never given this permission.
- The permission was granted on the wrong resource ID, for example the keyspace ID instead of the API ID.
- Someone saved the key in **Edit root key** and left the permission unchecked. Saving replaces the whole set.

A missing permission doesn't always return 403. Most endpoints that read or change a resource you named return a 404 for it instead, so a 404 doesn't prove the resource is gone. Check the root key's permissions before you decide the ID is wrong.

## How to fix

1. Grant the missing permission to the root key in the dashboard, or create a new root key with the right permissions.
2. Grant it as `resource.id.action`, such as `api.api_123.create_key` for one API or `api.*.create_key` for every API in the workspace.
3. If `detail` shows the permission as `unkey:v1:{workspace}:{path}#{action}`, the part after `#` is the action and the path is the resource. Grant the matching `resource.id.action`.

Give each service its own root key with only what it needs, so a leaked key can't do more. See [Root key permissions](/platform/root-keys/permissions).

Keys you check with `keys.verifyKey` never return this error. A failed permission check there comes back as `valid: false` with code `INSUFFICIENT_PERMISSIONS`.
