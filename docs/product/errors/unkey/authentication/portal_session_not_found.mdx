<Danger>`err:unkey:authentication:portal_session_not_found`</Danger>

```json Example
{
  "meta": {
    "requestId": "req_2c9a0jf23l4k567"
  },
  "error": {
    "detail": "Session is invalid, expired, or has already been used.",
    "status": 401,
    "title": "Unauthorized",
    "type": "https://unkey.com/docs/errors/unkey/authentication/portal_session_not_found"
  }
}
```

## What Happened?

This error is returned by `POST /v2/portal.exchangeCode` and any portal-authenticated endpoint when the supplied credential cannot be resolved. There are three common reasons:

- **Expired exchange code**: The exchange code returned by `portal.createSession` is valid for 15 minutes. After that it can no longer be exchanged.
- **Already-used exchange code**: Exchange codes are single-use. After the portal exchanges a code, it cannot be exchanged again.
- **Expired access token**: The access token is valid for 24 hours. After that, requests using it return this error.

## How To Fix

Create a fresh session from your backend and redirect the user again:

```bash
curl -X POST https://api.unkey.com/v2/portal.createSession \
  -H "Authorization: Bearer YOUR_ROOT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "slug": "my-portal",
    "externalId": "user_123",
    "permissions": ["api.*.read_key", "api.*.read_analytics"]
  }'
```

Then redirect the user to the returned `url`. The portal redeems the exchange code for a 24-hour access token stored in an httpOnly cookie.

If you have configured a `return_url` on your portal, expired browser sessions will automatically redirect there with `?reason=session_expired`. Use that hook to re-mint a session and bounce the user back into the portal seamlessly.

```typescript
// In your backend route handler
if (request.url.searchParams.get("reason") === "session_expired") {
  const { data } = await createPortalSession(currentUser);
  return Response.redirect(data.url, 302);
}
```

## Common Mistakes

- **Reusing an exchange code**: Exchange codes are single-use. Create a new session for every redirect.
- **Persisting exchange codes**: Don't persist exchange codes. They are short-lived and meant to be consumed immediately.
- **Skipping the exchange**: The portal must call `portal.exchangeCode` to redeem the exchange code for an access token.
- **Long-running tabs**: Users who keep the portal open beyond 24 hours need a fresh session.
