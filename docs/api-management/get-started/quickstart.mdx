Create a keyspace, issue a key with `keys.createKey`, and <Tooltip tip="keys.verifyKey looks up the presented key, runs its configured checks, and reports whether it is valid. Not domain verification or the Compute gateway policy.">verify</Tooltip> it with `keys.verifyKey`. Both are HTTPS calls to `api.unkey.com`, so they work from any language or host.

Already storing keys yourself? [Migrating keys](/api-management/keys/migrating-keys) imports your existing hashes so users keep the same keys.

## Initial Setup

Do these once in the dashboard before you write any code.

<Steps titleSize="h3">
  <Step title="Create a root key">
    Your backend calls the Unkey API with a root key. Open **Root Keys** in the dashboard sidebar, click **New Root Key**, and name it, for example `quickstart`. You need the workspace [admin role](/platform/workspace/team) to see **Root Keys**.

    <Frame>
      <img src="/images/dashboard/api-management--get-started-quickstart--root-key-name.png" alt="New Root Key panel with quickstart entered as the name and the permission templates below" />
    </Frame>

    Under **Permissions**, select the **Verify keys** template.

    <Frame>
      <img src="/images/dashboard/api-management--get-started-quickstart--root-key-template.png" alt="New Root Key panel with the Verify keys permission template highlighted" />
    </Frame>

    Click the policy to expand it, then select **Write** on the **Keys** row so the root key can also create keys. Click **Create key**.

    <Frame>
      <img src="/images/dashboard/api-management--get-started-quickstart--root-key-permissions.png" alt="Expanded Verify keys policy with Write and Verify selected on the Keys row and the Create key button" />
    </Frame>

    Copy the secret and store it as `UNKEY_ROOT_KEY`.

    <Warning>
      Unkey shows the root key only once. If you close the dialog without copying it, [rotate the key](/platform/root-keys/overview#rotate-a-root-key) or create a new one.
    </Warning>
  </Step>
  <Step title="Create a keyspace">
    A keyspace holds the keys for one product, environment, or tier. In the dashboard, open **Keyspaces (APIs)**, click **Create keyspace**, and name it.

    <Frame>
      <img src="/images/dashboard/api-management--get-started-quickstart--create-keyspace.png" alt="Create keyspace dialog with a name entered and the Create Keyspace button" />
    </Frame>

    Copy the **API ID** (`api_...`) from its settings page. You will need this ID to create keys.

    <Frame>
      <img src="/images/dashboard/api-management--get-started-quickstart--api-id.png" alt="Keyspace settings page with the API ID field highlighted" />
    </Frame>
  </Step>
</Steps>

## Key Actions

Use the language switcher to change the code samples.

<View title="curl">
  <Steps titleSize="h3">
    <Step title="Create a key">
      Call `keys.createKey` with the API ID. `name` is an internal label your users never see.

      ```bash
      curl -X POST https://api.unkey.com/v2/keys.createKey \
        -H "Authorization: Bearer $UNKEY_ROOT_KEY" \
        -H "Content-Type: application/json" \
        -d '{
          "apiId": "api_...",
          "name": "My first key"
        }'
      ```

      `data.key` is shown only once. Copy it now and give it to your user.

      ```json
      {
        "meta": { "requestId": "req_..." },
        "data": {
          "keyId": "key_...",
          "key": "..."
        }
      }
      ```
    </Step>
    <Step title="Verify the key">
      Run this on every incoming request. You don't pass an `apiId` because the key identifies its keyspace.

      ```bash
      curl -X POST https://api.unkey.com/v2/keys.verifyKey \
        -H "Authorization: Bearer $UNKEY_ROOT_KEY" \
        -H "Content-Type: application/json" \
        -d '{ "key": "<the key from the previous step>" }'
      ```
    </Step>
  </Steps>
</View>

<View title="TypeScript">
  <Steps titleSize="h3">
    <Step title="Install the SDK">
      ```bash
      npm install @unkey/api
      ```
    </Step>
    <Step title="Create a key">
      ```typescript create-key.ts
      import { Unkey } from "@unkey/api";

      const unkey = new Unkey({ rootKey: process.env.UNKEY_ROOT_KEY });

      const { data } = await unkey.keys.createKey({
        apiId: "api_...",
        name: "My first key",
      });

      // Shown once. Store it or send it to your user now.
      console.log(data.key);
      ```
    </Step>
    <Step title="Verify the key">
      Run this on every incoming request. You don't pass an `apiId` because the key identifies its keyspace.

      ```typescript verify-key.ts
      const { data } = await unkey.keys.verifyKey({ key: incomingKey });

      if (!data.valid) {
        // data.code says why: NOT_FOUND, EXPIRED, RATE_LIMITED, ...
        throw new Error(`denied: ${data.code}`);
      }

      console.log(data.keyId);
      ```
    </Step>
  </Steps>
</View>

<View title="Go">
  <Steps titleSize="h3">
    <Step title="Install the SDK">
      ```bash
      go get github.com/unkeyed/sdks/api/go/v3@latest
      ```
    </Step>
    <Step title="Create a key">
      ```go main.go
      package main

      import (
      	"context"
      	"fmt"
      	"os"

      	unkey "github.com/unkeyed/sdks/api/go/v3"
      	"github.com/unkeyed/sdks/api/go/v3/models/components"
      )

      func main() {
      	client := unkey.New(unkey.WithSecurity(os.Getenv("UNKEY_ROOT_KEY")))

      	res, err := client.Keys.CreateKey(context.Background(), components.V2KeysCreateKeyRequestBody{
      		APIID: "api_...",
      		Name:  unkey.String("My first key"),
      	})
      	if err != nil {
      		panic(err)
      	}

      	// Shown once. Store it or send it to your user now.
      	fmt.Println(res.V2KeysCreateKeyResponseBody.Data.Key)
      }
      ```
    </Step>
    <Step title="Verify the key">
      Run this on every incoming request. You don't pass an `apiId` because the key identifies its keyspace.

      ```go verify.go
      res, err := client.Keys.VerifyKey(ctx, components.V2KeysVerifyKeyRequestBody{
      	Key: incomingKey,
      })
      if err != nil {
      	return err
      }

      data := res.V2KeysVerifyKeyResponseBody.Data
      if !data.Valid {
      	// data.Code says why: NOT_FOUND, EXPIRED, RATE_LIMITED, ...
      	return fmt.Errorf("denied: %s", data.Code)
      }
      ```
    </Step>
  </Steps>
</View>

## Reading the verification response

Verification returns HTTP 200 even when the key is rejected. Check `data.valid`. When it's `false`, `data.code` says why.

```json
{
  "meta": { "requestId": "req_..." },
  "data": {
    "valid": true,
    "code": "VALID",
    "keyId": "key_...",
    "name": "My first key",
    "enabled": true
  }
}
```

Fields such as `credits`, `ratelimits`, `meta`, and `identity` appear once you configure them on the key. [Verifying keys](/api-management/keys/verifying-keys) lists every field and `code` value.
