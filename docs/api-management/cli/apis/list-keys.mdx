List the keys of an API. Results come in pages. Pass the `cursor` from one response to get the next page. Calls `POST /v2/apis.listKeys`. See [Listing keys](/api-management/keyspaces/listing-keys).

## Usage

```bash
unkey keys list --api-id=<api id> [flags]
```

## Flags

<ParamField body="--api-id" type="string" required>
  Id of the API whose keys to list.
</ParamField>

<ParamField body="--cursor" type="string">
  Cursor from the previous response's `pagination.cursor`.
</ParamField>

<ParamField body="--decrypt" type="boolean" default="false">
  Include the plaintext key in each result. Only keys created with `--recoverable` have one, and the root key needs `decrypt_key`. The call fails with `412` unless the keyspace has key encryption turned on, which only we can do, through a support request.
</ParamField>

<ParamField body="--external-id" type="string">
  Return only keys linked to the identity with this external id. An external id that matches no identity returns an empty page, not an error.
</ParamField>

<ParamField body="--limit" type="integer">
  Maximum number of keys per page. 1 to 100. Defaults to 100.
</ParamField>

<ParamField body="--revalidate-keys-cache" type="boolean" default="false">
  When true, reads keys and their identities from the primary database to avoid replica lag. When false or omitted, reads from a replica, which may not reflect recent changes. Primary reads can have higher latency, depending on your region.
</ParamField>

## Required permissions

`api.*.read_key` or `api.<apiId>.read_key`, together with `api.*.read_api` or `api.<apiId>.read_api`. `--decrypt` also needs `api.*.decrypt_key` or `api.<apiId>.decrypt_key`. Without the permission you get a 404, so the response doesn't reveal whether the API exists. If your key can read the keys but not decrypt them, `--decrypt` fails with a 403 that names the missing permission. See [Root key permissions](/platform/root-keys/permissions).

## Examples

```bash First page
unkey keys list --api-id=api_1234abcd --limit=50
```

```bash Keys of one identity
unkey keys list --api-id=api_1234abcd --external-id=user_1234abcd
```

Or send the whole request as JSON:

```bash Raw body
unkey keys list --body='{"apiId":"api_1234abcd","limit":50,"externalId":"user_1234abcd"}'
```
