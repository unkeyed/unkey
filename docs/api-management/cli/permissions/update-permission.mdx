Update the name, slug, or description of a permission, identified by its ID or slug.

Omitted fields keep their current values. A request with no fields to update returns the stored permission without a write.

Important: Keys and roles reference the permission by ID, so they keep the permission after a slug change. Key verification can return the old slug for a short time while caches refresh. A slug that another permission in your workspace already uses returns 409.

## Usage

```bash
unkey permissions update --permission=<permission> [flags]
```

## Flags

<ParamField body="--description" type="string">
  New description for the permission. Omit this field to keep the current description. Send null or an empty string to remove it. Pass `--description=` to remove it, or use `--body` with `description: null`.
</ParamField>

<ParamField body="--name" type="string">
  New human-readable name for the permission. Omit this field to keep the current name.
</ParamField>

<ParamField body="--permission" type="string" required>
  The permission to update. Pass the permission ID (`perm_...`) or its current slug.
</ParamField>

<ParamField body="--slug" type="string">
  New slug for the permission. Keys and roles that have this permission get the new slug in verification responses. The slug must be unique in your workspace. Omit this field to keep the current slug.
</ParamField>

## Required permissions

Your root key must have the following permission:

- `unkey:v1:<workspace_id>:projects/<project_id>/rbac/permissions/<permission_id>#write`

See [Root key permissions](/platform/root-keys/permissions).

## Examples

```bash
unkey permissions update --permission=documents-read --name="Read documents" --slug=documents.read
```

```bash
unkey permissions update --permission=documents.read --description=
```

Send the request body as JSON:

```bash
unkey permissions update --body='{"permission":"documents.read","description":null}'
```

## API endpoint

The command calls `POST /v2/permissions.updatePermission` and prints its response. See the <a href="https://github.com/unkeyed/unkey/blob/main/svc/api/openapi/spec/paths/v2/permissions/updatePermission/index.yaml" target="_blank">endpoint definition</a> for the HTTP contract. Request fields use camelCase in `--body`.
