Create a permission. You grant the slug to keys and roles, and check it with `keys verify-key --permissions`. Calls `POST /v2/permissions.createPermission`. See [Roles and permissions](/api-management/authorization/roles-and-permissions).

## Usage

```bash
unkey permissions create --name=<name> --slug=<slug> [flags]
```

## Flags

<ParamField body="--name" type="string" required>
  Display name, 1 to 512 characters.
</ParamField>

<ParamField body="--slug" type="string" required>
  Name used when granting and checking the permission. Unique per workspace. Reusing one returns 409 [`err:unkey:data:permission_already_exists`](/errors/unkey/data/permission_already_exists). 1 to 128 characters matching `^[a-zA-Z0-9_:\-\.\*]+$`: letters, digits, underscores, colons, hyphens, periods, and asterisks.
</ParamField>

<ParamField body="--description" type="string">
  What the permission allows, for the dashboard. Up to 512 characters.
</ParamField>

## Required permissions

`rbac.*.create_permission`. See [Root key permissions](/platform/root-keys/permissions).
