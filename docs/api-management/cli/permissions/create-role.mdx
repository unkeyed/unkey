Create a role. A role groups permissions so you can give a key many at once. Calls `POST /v2/permissions.createRole`. See [Roles and permissions](/api-management/authorization/roles-and-permissions).

## Usage

```bash
unkey roles create --name=<name> [flags]
```

## Flags

<ParamField body="--name" type="string" required>
  Role name, 1 to 128 characters. Unique per workspace. Reusing one returns 409 [`err:unkey:data:role_already_exists`](/errors/unkey/data/role_already_exists). Keys refer to roles by name.
</ParamField>

<ParamField body="--description" type="string">
  What the role is for.
</ParamField>

<ParamField body="--permissions" type="string[]">
  Comma-separated permission slugs to attach. Slugs that don't exist yet are created. Each slug is 1 to 128 characters matching `^[a-zA-Z0-9_:\-\.\*]+$`, the same as `unkey permissions create`.
</ParamField>

## Required permissions

`rbac.*.create_role`, plus `rbac.*.add_permission_to_role` when `--permissions` is given. Creating new slugs also needs `rbac.*.create_permission`. See [Root key permissions](/platform/root-keys/permissions).

## Examples

```bash Create with permissions
unkey roles create --name=api_reader --permissions=documents.read,settings.view
```

Or send the whole request as JSON:

```bash Raw body
unkey roles create --body='{"name":"api_reader","description":"Read-only access","permissions":["documents.read"]}'
```
