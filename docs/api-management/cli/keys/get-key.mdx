Read a key by id: its name, identity, permissions, roles, credits, rate limits, and expiry. Calls `POST /v2/keys.getKey`. See [Looking up keys](/api-management/keys/looking-up-keys).

## Usage

```bash
unkey keys get --key-id=<key id> [flags]
```

## Flags

<ParamField body="--key-id" type="string" required>
  Id of the key, starting with `key_`.
</ParamField>

<ParamField body="--decrypt" type="boolean" default="false">
  Include the plaintext key. Works only for keys created with `--recoverable` and needs `decrypt_key`. Fails with `412` unless the keyspace has key encryption turned on, which only we can do, through a support request.
</ParamField>

### Shared flags

Every resource command takes these. See [CLI output and shared flags](/platform/cli/output-and-flags).

<ParamField body="--root-key" type="string">
  Root key used for the request. Falls back to `UNKEY_ROOT_KEY`, then stored credentials, including a CLI session. See [CLI authentication](/platform/cli/authentication) for the full precedence order.
</ParamField>

<ParamField body="--api-url" type="string" default="https://api.unkey.com">
  Base URL of the API. Falls back to `UNKEY_API_BASE_URL`. You don't normally need to set it.
</ParamField>

<ParamField body="--config" type="string" default="~/.unkey/config.toml">
  Path of the TOML config file. Falls back to `UNKEY_CONFIG`. An explicit `--config` takes precedence over a stored CLI session. Browser login stores a session, not a root key in this file. See [CLI authentication](/platform/cli/authentication).
</ParamField>

<ParamField body="--output" type="enum" default="human">
  <CLIOutput />
</ParamField>

<ParamField body="--debug" type="boolean">
  Print the successful response's request ID to stderr, separate from stdout.
</ParamField>

<ParamField body="--json" type="boolean">
  Print the full response as JSON. Takes precedence over a valid `--output` or `UNKEY_OUTPUT` value.
</ParamField>

<ParamField body="--body" type="string">
  Send this JSON as the whole request body instead of using the command's flags. You can't combine it with them.
</ParamField>

## Required permissions

`api.*.read_key` or `api.<apiId>.read_key`. `--decrypt` also needs `api.*.decrypt_key` or `api.<apiId>.decrypt_key`. See [Root key permissions](/platform/root-keys/permissions).

## Examples

```bash Read a key
unkey keys get --key-id=key_1234abcd
```

```bash Read a recoverable key's plaintext
unkey keys get --key-id=key_1234abcd --decrypt
```

Or send the whole request as JSON:

```bash Raw body
unkey keys get --body='{"keyId":"key_1234abcd","decrypt":false}'
```
