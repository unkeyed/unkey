Read a [portal](/api-management/portal/overview): its branding, whether it's enabled, and the keyspace or app behind it. Look it up by ID or slug, or by the keyspace or app it serves to check whether one has a portal. Pass exactly one of the three. More than one fails with 400. Calls `POST /v2/portal.getPortal`.

## Usage

```bash
unkey portals get (--portal=<portal> | --keyspace-id=<id> | --app-id=<id>) [flags]
```

## Flags

<ParamField body="--portal" type="string">
  Portal id or slug.
</ParamField>

<ParamField body="--keyspace-id" type="string">
  Find the portal for this keyspace.
</ParamField>

<ParamField body="--app-id" type="string">
  Find the portal for this app.
</ParamField>

## Required permissions

`portal.*.read_portal` or `portal.<portalId>.read_portal`. Without it you get a 404, so a 404 means either there's no such portal or you don't have permission. See [Root key permissions](/platform/root-keys/permissions).

## Examples

```bash By handle
unkey portals get --portal=acme-portal
```

```bash By the keyspace it serves
unkey portals get --keyspace-id=ks_1234abcd
```

Or send the whole request as JSON:

```bash Raw body
unkey portals get --body='{"portal":"acme-portal"}'
```
