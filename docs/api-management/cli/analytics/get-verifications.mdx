Query key verification data with SQL. Use the `key_verifications_v1` table, or the rolled-up `key_verifications_per_minute_v1`, `key_verifications_per_hour_v1`, `key_verifications_per_day_v1`, and `key_verifications_per_month_v1`. The query must be one `SELECT` with a `FROM`, using only allowed functions and documented columns. The rules and their error codes are on [`err:user:bad_request:invalid_analytics_query`](/errors/user/bad_request/invalid_analytics_query). Responses over 4 MiB fail with [`err:user:unprocessable_entity:query_memory_limit_exceeded`](/errors/user/unprocessable_entity/query_memory_limit_exceeded). Query time and result rows are limited too. Calls `POST /v2/analytics.getVerifications`. See [key_verifications tables](/api-management/analytics/tables/key-verifications), [Analytics restrictions and quotas](/api-management/analytics/restrictions-and-quotas), and [Analytics troubleshooting](/api-management/analytics/troubleshooting).

## Usage

```bash
unkey analytics verifications --query=<query> [flags]
```

## Required permissions

`api.*.read_analytics`, or `api.<apiId>.read_analytics` for one or more APIs, which limits results to those keyspaces. See [Root key permissions](/platform/root-keys/permissions).

## Examples

```bash Outcomes in the last day
unkey analytics verifications --query="SELECT outcome, count() AS n FROM key_verifications_v1 WHERE time > now() - toIntervalDay(1) GROUP BY outcome"
```

Or send the whole request as JSON:

```bash Raw body
unkey analytics verifications --body='{"query":"SELECT outcome, count() AS n FROM key_verifications_v1 WHERE time > now() - toIntervalDay(1) GROUP BY outcome"}'
```
