Delete an override. After that, the identifier gets the limit that `ratelimit limit` sends. Calls `POST /v2/ratelimit.deleteOverride`. See [Rate limit overrides](/api-management/ratelimiting/overrides).

## Usage

```bash
unkey ratelimit overrides delete --identifier=<identifier> --namespace=<namespace> [flags]
```

## Flags

<ParamField body="--yes" type="boolean">
  <CLIConfirmation />
</ParamField>

<ParamField body="--identifier" type="string" required>
  The override's identifier, exactly as stored. For a wildcard override, pass the pattern, such as `premium_*`, not an identifier it matches.
</ParamField>

<ParamField body="--namespace" type="string" required>
  Namespace id or name.
</ParamField>

## Required permissions

`ratelimit.*.delete_override` or `ratelimit.<namespace_id>.delete_override`. Without the permission you get a 404, so the response doesn't reveal whether the resource exists. If your key can read the override, you get a 403 that names the missing permission instead. See [Root key permissions](/platform/root-keys/permissions).
