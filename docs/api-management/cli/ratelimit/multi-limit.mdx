Check several <Tooltip tip="Here: the standalone rate limiting API and its overrides. Not key rate limits or gateway policies.">rate limit</Tooltip>s at once. `data.passed` is true only when every check passes. Each check's result is in `data.limits`. If one check fails, none of the limits are charged. A deleted namespace anywhere in the list fails the whole request with 410 Gone and [`err:unkey:data:ratelimit_namespace_gone`](/errors/unkey/data/ratelimit_namespace_gone). Calls `POST /v2/ratelimit.multiLimit`. See [Limit and multi-limit](/api-management/ratelimiting/limit-and-multi-limit).

## Usage

```bash
unkey ratelimit multi-limit --limits=<limits> [flags]
```

`--body` takes a JSON array, not an object.

## Flags

<ParamField body="--limits" type="string" required>
  JSON array of 1 to 100 checks, each with `namespace`, `identifier`, `limit`, `duration`, and optional `cost`, the same fields `ratelimit limit` takes as flags.
</ParamField>

## Required permissions

`ratelimit.*.limit`, or `ratelimit.<namespace_id>.limit` for every namespace in the request. Namespaces created on first use also need `ratelimit.*.create_namespace`. See [Root key permissions](/platform/root-keys/permissions).

## Examples

```bash Two limits
unkey ratelimit multi-limit --limits='[{"namespace":"api.requests","identifier":"user_abc","limit":100,"duration":60000},{"namespace":"api.daily","identifier":"user_abc","limit":5000,"duration":86400000}]'
```

Or send the whole request as JSON:

```bash Raw body
unkey ratelimit multi-limit --body='[{"namespace":"api.requests","identifier":"user_abc","limit":100,"duration":60000}]'
```
