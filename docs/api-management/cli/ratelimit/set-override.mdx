Give one identifier, or a wildcard pattern, its own limit and window. It's used instead of the values sent to `ratelimit limit`. Setting it again replaces the old one. An exact identifier beats a pattern. If an identifier matches two patterns, such as `premium_*` and `*_eu`, there's no guarantee which applies, so keep patterns from overlapping. Calls `POST /v2/ratelimit.setOverride`. See [Rate limit overrides](/api-management/ratelimiting/overrides).

## Usage

```bash
unkey api ratelimit set-override --duration=<duration> --identifier=<identifier> --limit=<limit> --namespace=<namespace> [flags]
```

## Flags

<ParamField body="--duration" type="integer" required>
  Window length in milliseconds, at least 1000. It doesn't have to match the window the caller sends.
</ParamField>

<ParamField body="--identifier" type="string" required>
  Identifier to override, or a pattern with `*` such as `premium_*`.
</ParamField>

<ParamField body="--limit" type="integer" required>
  Maximum operations allowed in the window. The API accepts 0, but checks against it then fail with a server error instead of being denied. To nearly block an identifier, use 1 with a long `--duration`.
</ParamField>

<ParamField body="--namespace" type="string" required>
  Namespace id or name. The namespace must already exist.
</ParamField>

## Required permissions

`ratelimit.*.set_override` or `ratelimit.<namespace_id>.set_override`. See [Root key permissions](/platform/root-keys/permissions).

## Examples

```bash Raise one user's limit
unkey api ratelimit set-override --namespace=api.requests --identifier=premium_user_123 --limit=1000 --duration=60000
```

```bash Pattern override
unkey api ratelimit set-override --namespace=api.requests --identifier='premium_*' --limit=500 --duration=60000
```

Or send the whole request as JSON:

```bash Raw body
unkey api ratelimit set-override --body='{"namespace":"api.requests","identifier":"premium_*","limit":500,"duration":60000}'
```
