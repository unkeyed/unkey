<Danger>`err:unkey:application:precondition_failed`</Danger>

Your request is valid, but something about your setup has to change first. You get HTTP 412, and `detail` says what.

```json Example response
{
  "meta": {
    "requestId": "req_2c9a0jf23l4k567"
  },
  "error": {
    "detail": "The requested API is not set up to handle keys.",
    "status": 412,
    "title": "Precondition Failed",
    "type": "/errors/unkey/application/precondition_failed"
  }
}
```

## Likely causes

In API Management:

- The API isn't set up for keys (`The requested API is not set up to handle keys.`).
- You asked for key recovery (`recoverable: true` or `decrypt: true`) on an API that doesn't store recoverable keys.
- A rate limit you named in `keys.verifyKey` isn't set on the key or its identity.

In Compute:

- The workspace has no active Compute plan, or compute is paused because the workspace reached its spend limit.
- You asked for a git deployment, but the app has no connected GitHub repository, or the Unkey GitHub App isn't installed or can't access the repository.
- You redeployed a deployment that never produced an image.
- The domain you're verifying is already verified.

## How to fix

Do what `detail` says, then retry:

- Use an API with key support, or check the API ID.
- Turn on recoverable keys for the API before you ask for `recoverable: true` or `decrypt: true`.
- Set the named rate limit on the key or identity before you check it.
- Connect the repository, or install the GitHub App from the link in the message.
- Choose a Compute plan under [Plans](/platform/billing/plans), or raise or remove the spend budget under **Settings > Billing**.
- For an already verified domain, there's nothing to do.
