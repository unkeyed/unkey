<Danger>`err:unkey:application:deployment_not_awaiting_approval`</Danger>

You asked to authorize a deployment that is not waiting for approval. You get HTTP 412.

```json Example response
{
  "meta": {
    "requestId": "req_2c9a0jf23l4k567"
  },
  "error": {
    "detail": "The deployment is not awaiting approval. Its status is building.",
    "status": 412,
    "title": "Precondition Failed",
    "type": "/errors/unkey/application/deployment_not_awaiting_approval"
  }
}
```

## Likely causes

- Someone already authorized the deployment.
- The deployment was cancelled or superseded before it was authorized.
- The deployment never needed approval. Only deployments from forked pull requests wait for approval.

## How to fix

1. Read the deployment with `deployments.getDeployment` and check its `status`.
2. If the status is past `awaiting_approval`, the deployment is already running its build. There is nothing to do.
3. If the deployment was cancelled or superseded, push a new commit to create a new deployment.

## Related errors

- [`err:unkey:application:precondition_failed`](/errors/unkey/application/precondition_failed): the workspace has no Compute plan or is paused at its spend limit, which also blocks authorization.
- [`err:unkey:data:deployment_not_found`](/errors/unkey/data/deployment_not_found): the deployment does not exist, or your root key cannot write to it.
