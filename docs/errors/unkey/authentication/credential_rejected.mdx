<Danger>`err:unkey:authentication:credential_rejected`</Danger>

The refresh token for a CLI session was not accepted. You get HTTP 401.

```json Example response
{
  "meta": {
    "requestId": "req_2c9a0jf23l4k567"
  },
  "error": {
    "detail": "The refresh token is invalid. Run unkey login again.",
    "status": 401,
    "title": "Unauthorized",
    "type": "/errors/unkey/authentication/credential_rejected"
  }
}
```

## Likely causes

- The refresh token was already exchanged for a new one. Reusing the old token revokes the session.
- The CLI session expired or was revoked from the dashboard.
- The token was copied incompletely, or it belongs to a different API.

## How to fix

1. Run `unkey login` and approve the new code.
2. If a second CLI process refreshed at the same time, log in again. Only the latest refresh token works.
3. Confirm `UNKEY_API_URL` points at the API that issued the session.

## Related errors

- [`err:unkey:authentication:key_not_found`](/errors/unkey/authentication/key_not_found): a root key in the Authorization header is not recognized.
- [`err:unkey:authentication:malformed`](/errors/unkey/authentication/malformed): the Authorization header is not `Bearer <token>`.
- [`err:unkey:authorization:forbidden`](/errors/unkey/authorization/forbidden): the refresh token was valid, but the member no longer has the session's permissions.
