<Danger>`err:unkey:data:project_not_found`</Danger>

The project you referenced doesn't exist in your workspace. You get HTTP 404. Some Compute calls, including deployment calls, use the shorter message `Project not found.`

```json Example response
{
  "meta": {
    "requestId": "req_2c9a0jf23l4k567"
  },
  "error": {
    "detail": "The requested project does not exist.",
    "status": 404,
    "title": "Not Found",
    "type": "/errors/unkey/data/project_not_found"
  }
}
```

## Likely causes

- The ID or slug is wrong, or the project was renamed and you're using the old slug.
- The project is in another workspace.
- Your root key doesn't have permission on the project. Most of these endpoints return this 404 instead of a 403.
- You just tried to create the project and the create failed. New projects are available right away.

## How to fix

1. List projects with `projects.listProjects` and use the returned ID or slug.
2. Check that the root key has the permission the endpoint needs on the project.

## Related errors

- [`err:unkey:data:app_not_found`](/errors/unkey/data/app_not_found): the app within the project doesn't exist.
- [`err:unkey:data:project_already_exists`](/errors/unkey/data/project_already_exists): a project with that slug already exists.
- [`err:unkey:application:protected_resource`](/errors/unkey/application/protected_resource): the project can't be deleted while delete protection is on.
