<Danger>`err:frontline:capacity:openapi_validation_busy`</Danger>

import { ProductLink } from "/snippets/product-link.jsx";

The request matches an [OpenAPI validation policy](/compute/gateway/openapi-validation), and the gateway is already holding as many request bodies for that check as it allows. It rejects the request before it reads the body. You get `503 Service Unavailable`.

```json Example response
{
  "meta": {
    "requestId": "req_3k2j1h0g9f8e7d6c"
  },
  "error": {
    "code": "err:frontline:capacity:openapi_validation_busy",
    "message": "The gateway is validating too many request bodies right now. Retry shortly."
  }
}
```

Browsers get the same error as an HTML page.

## If you're calling an API hosted on Unkey

Retry after a short delay, with backoff. Smaller request bodies are less likely to get this error.

## If you own this API

To check a body, the gateway holds the whole body in memory. Each gateway instance limits the total size of the bodies it holds at once, so that many large requests can't use up its memory. Requests with a large body, or with no `Content-Length` header, need the most room and get this error first.

If you see it often without unusual traffic, send smaller bodies, or contact support.

</ProductLink>
